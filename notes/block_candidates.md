# Block candidates

Composition evidence gathered from atom-only gallery flows. Candidates stay unextracted until their repeated anatomy and variation are clear.

## Auth and onboarding

| Candidate             | Evidence                                                                                                                                                                                                          | Stable anatomy                                                                                                                            | Variation to preserve                                                                       | Decision                                                                                                                                            |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Authentication shell  | Sign-in and password recovery now share one semantic page landmark with medium-width constraint, gutters, and vertical rhythm across eleven form, loading, validation, completion, expiration, and mobile states. | Required direct content inside `main` → `Container(:md)` → the then-current `VStack` (now column `Flex`); no visible regions or variants. | Caller-owned Card, headings, forms, copy, branding, Turbo lifecycle, and application state. | Extract `AuthShell` only. | Token recovery status | Password reset, email verification, and invitation acceptance each pair an Alert explaining token state with one recovery Button.                                                                                 | Status title, specific explanation, recovery action.                                                                                      | Expired versus invalid intent, resend versus human support, privacy-preserving copy.        | Candidate; keep token policy and messages application-owned.                                                                                        |
| Success handoff       | Sign-in, account creation, email verification, invitation acceptance, and onboarding complete with a success Alert and one primary continuation.                                                                  | Success status plus a single next action.                                                                                                 | Destination, retained identity/workspace context, Turbo replacement target.                 | Candidate; likely a narrow status-and-action block rather than an auth-specific shell.                                                              |
| Onboarding progress   | Seven onboarding states render a four-step ordered list with completed and current semantics.                                                                                                                     | Ordered steps, current step, completed predecessors, step count Badge.                                                                    | Step labels, optional/skipped steps, resume metadata.                                       | Hold: repeated states have only one product consumer so far.                                                                                        |
| Consent field         | Invitation acceptance, account creation, and onboarding review use a required Checkbox-backed Field before a primary submit.                                                                                      | Native checkbox, real submitted values, required semantics.                                                                               | Terms text and policy links.                                                                | Do not extract; existing Field and Checkbox atoms already cover the stable behavior.                                                                |

At this evidence stage, `AppShell` remained deferred because no product chrome existed beyond the gallery itself; it was later accepted after the application-layout mandate and reference audit supplied the missing evidence. `MarketingShell` remains deferred because no stable public or marketing shell responsibility has been established.

## Layout extraction decision

The first layout wave deliberately narrows the speculative Phase 3 list to structures repeated across the atom-only flows.

Supersession note: this table preserves the evidence and first extraction decision. The public API later removed `VStack` and `HStack` in favor of `Flex(dir:)`, expanded Grid to responsive columns `1..12`, and adopted the fixed mobile-first `sm md lg xl 2xl` property grammar. The current API lives in the [component contracts](../docs/component_contracts.md).

| Primitive   | Evidence                                                                                                                                                              | Closed responsibility                                                                                                                          | Decision                                                                                                                                    |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `VStack`    | Forms, status handoffs, record cards, dense dashboard sections, and every flow page repeat vertical rhythm with intrinsic actions or deliberately stretched surfaces. | Gaps `none`, `xs`, `sm`, `md`, `lg`, `xl`; alignment `start`, `center`, `stretch`; direct Phlex content.                                       | Historical extraction; superseded by `Flex(dir: :col)`.                                                                                     |
| `HStack`    | Header/action rows, status/action pairs, compact record controls, and wrapping mobile action groups repeat horizontal rhythm and three distributions.                 | Shared gaps; alignment `start`, `center`, `stretch`; justification `start`, `end`, `between`; boolean wrapping.                                | Historical extraction; superseded by `Flex(dir: :row)`.                                                                                     |
| `Grid`      | Dashboard metrics and billing plan comparison repeat a three-column equal-track collection that must become one column on narrow screens.                             | Exactly `cols: 3`; equal `minmax(0, 1fr)` tracks; one Nitro-owned 48rem collapse.                                                              | Historical constraint; superseded by responsive `cols: 1..12` and gap values.                                                               |
| `Container` | Auth/forms, readable summaries, tables, and broad collections repeatedly use the existing `--nk-content-sm` through `--nk-content-xl` boundaries.                     | Sizes `sm`, `md`, `lg`, `xl`; centered maximum width; direct Phlex content.                                                                    | Extract. Full-width content omits Container instead of selecting a `full` variant.                                                          |
| `Spacer`    | No atom-only flow uses an elastic empty item; existing row spacing is fixed and distribution is `start`, `end`, or `between`.                                         | None proven.                                                                                                                                   | Defer. `Flex#justify` handles current cases more directly.                                                                                  |
| `Split`     | Only the settings navigation suggests a two-pane layout, and its block boundary is still unsettled.                                                                   | Ratio, slot ownership, and responsive order are not yet proven.                                                                                | Defer until a second domain confirms the same structure.                                                                                    |
| `Frame`     | Dashboard chart normal, dense, and mobile states now require one responsive 16:9 SVG boundary, while loading and error preserve the same semantic figure region.      | Aspect-ratio child sizing and availability-state pressure are concrete; a closed ratio vocabulary and non-chart applicability remain unproven. | Defer until a second media, preview, or visualization consumer confirms a general primitive and outweighs the Turbo Frame naming collision. |

## Navigation block extraction decision

The navigation wave keeps product state and route calculations in the application while extracting only repeated placement and semantic boundaries.

| Block            | Evidence                                                                                                                                                                         | Closed responsibility                                                                                                               | Decision                                                                                                                      |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `SettingsLayout` | All fourteen settings states repeat one labelled section navigation before one active content region, with wide and mobile pressure.                                             | Exactly one native `navigation(label:)` and one neutral `content` region; wide two-region layout and the shared 48rem narrow stack. | Extract. Destinations, order, current state, authorization, labels, and nested components remain caller-owned.                |
| `Toolbar`        | Profile, security, notification, integration, and appearance settings repeatedly place intrinsic status or copy opposite one or more actions, including long and loading states. | Optional leading and trailing regions, each at most once and at least one total; wide between/wrap and shared 48rem narrow stack.   | Extract as a neutral layout block. Deliberately omit `role=toolbar`, action arrays, sticky behavior, density, and registries. |
| `PaginationBar`  | User index, filtered user search, and invoice history prove cross-domain first, middle, and final boundaries with summaries, preserved queries, and accessible ellipses.         | Optional non-empty summary plus exactly one typed `NitroKit::Pagination`; placement and shared 48rem narrow stack only.             | Extract. Counts, result ranges, filters, routes, current-page math, and Pagination items remain caller-owned.                 |
| `ProgressSteps`  | Nine onboarding states repeat the same four-step ordered progress list, but all evidence belongs to one product workflow.                                                        | No cross-domain vocabulary proven.                                                                                                  | Defer. Keep the onboarding list application-owned until a second multi-step consumer establishes shared semantics.            |
