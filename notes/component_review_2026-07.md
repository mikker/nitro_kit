# Nitro Kit component review — July 2026

This ledger consolidates the primary-agent review, two specialist audits, and an independent read-only Claude Code review run with the Fable model. The review covered every Ruby component, every Nitro Stimulus controller, component CSS, focused tests, and gallery examples.

Decision vocabulary:

- **Keep** — the current responsibility and implementation boundary are sound.
- **Tighten** — keep the component, but correct a focused API, semantic, or test gap.
- **Refactor** — preserve the product capability while materially simplifying its structure or progressive behavior.
- **Remove** — the platform or another Nitro component already owns the same capability.

## JavaScript controllers

| Controller        | Decision                   | Reason to exist / required change                                                                                                                |
| ----------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| accordion         | Remove                     | Native `details`/`summary` and shared `name` cover the behavior with a better no-JS baseline.                                                    |
| app-shell         | Refactor                   | Retain responsive orchestration only; delegate modal focus/inert/Escape/scroll behavior to `<dialog>`. Avoid stale cached targets across morphs. |
| appearance        | Keep                       | Requests preference changes and subscribes to the document runtime; persistence/system behavior cannot be CSS-only.                              |
| combobox          | Keep, refactor baseline    | Search/filter/active-descendant behavior is justified, but enhancement must start from a truthful submitted control.                             |
| dialog            | Remove or minimal fallback | Native command invokers and `<dialog>` own modal open/close. Do not promise light-dismiss where support is not reasonable.                       |
| dropdown          | Minimize                   | Popover owns toggle, Escape, top layer, and light dismiss. Keep only chosen APG keyboard semantics if the component remains a menu.              |
| dropzone          | Split                      | Selection/preview/validation and Active Storage transport are separable responsibilities. Preserve native input fallback and complete cleanup.   |
| progressive-image | Keep small                 | Load/error/decode state is not expressible in CSS; current revision and teardown design is strong.                                               |
| tabs              | Keep                       | There is no native tabs primitive; APG roving focus and activation need behavior. Add enhancement state and morph coverage.                      |
| toast             | Keep small                 | Timers, pause/resume, dismissal, and removal need behavior. Ensure every timer is cleared and auto-dismiss is opt-in.                            |
| tooltip           | Minimize                   | CSS owns pointer/focus display; JavaScript is only justified for explicit Escape dismissal until native interest invokers mature.                |

## Cross-cutting decisions

- Components remain a flat alphabetical gallery collection. Blocks and full examples become explicit nested categories owned by the catalog model.
- Responsive previews must resize an iframe viewport. Nitro responsive values use viewport media queries, so resizing an ordinary container would not exercise breakpoints.
- Native replacement is accepted only when it improves progressive behavior and semantics. “Less JavaScript” is not sufficient reason to weaken combobox, tabs, upload, appearance, or lifecycle behavior.
- All retained controllers need declarative actions where practical, deterministic teardown, and Turbo morph/cache coverage proportional to their state.

Implementation is tracked under `nk-onge` and its child tickets; ticket state is the source of truth for which recommendations have shipped.

- `nk-a8dk` / `nk-gqqt` — shipped the nested catalog IA and real iframe viewport previews. A visibility observer also covers controllers that connect while their Responsive tab is hidden.
- `nk-0je5` — shipped native disclosure, dialog-command, Popover, and CSS-tooltip ownership for Accordion, Dialog, Dropdown, and Tooltip.
- `nk-vt57` — shipped the accepted structural, semantic, accessible-name, truthful-state, and progressive-baseline corrections across alerts, actions, checkable controls, combobox, tables, tabs, toast, pagination, images, and compound blocks.
- `nk-kt79` — shipped native-dialog AppShell ownership and retained-controller lifecycle fixes. Dropzone now delegates pure file rules, shared form locking, and Active Storage request lifetime to small modules while keeping native input selection as its fallback. Appearance, Combobox, Tabs, Toast, and ProgressiveImage reconcile replaced targets and clean transient resources.

The remaining **Tighten** notes are deliberately recorded review guidance, not hidden unfinished work. They concern lower-risk API ergonomics and stricter validation (for example derived group IDs, scalar coercion, type-specific option rejection, and the Datepicker removal candidate). They do not invalidate current markup or progressive behavior and can be accepted independently in later API work.
